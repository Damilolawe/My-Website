# Postdeployment audit repairs

Velocity customer color overrides now cover the authored navigation, mobile
menu, chapter surfaces and footer, plus a secondary-color hero overlay. Original
images, geometry and uncustomized source designs remain intact. Surface text
colors are selected by actual WCAG contrast, with a black fallback when needed.
Browser and Edge copies share identical rendering logic.

Signature package metadata now describes five pages tailored to the selected
design rather than promising RunwayML-specific chapter names. The copy-only SQL
was applied and verified in production; it preserves package prices, terms
versions, allowed templates and existing order snapshots. The release script
repeats this correction safely for consistency.

The Premium card no longer repeats its introductory description in the feature
list. Catalog names are Folio, Terminal and Orbit; authored preview identities
are preserved. Canonical tags identify the primary domain, and account/admin
pages request noindex.

Validation: `node scripts/qa-velocity-colors.mjs` checks 40 combinations across
five chapters, two viewport widths (390/1440), two appearance modes and two
secondary colors. It checks actual computed header/footer/content colors,
mobile-menu visibility, horizontal overflow and text contrast (at least 4.5:1).
The tested minimum surface-text contrast was 5.01:1. Full build and 939-page
static validation passed. Run the existing Node suite after the build.

Only the package-copy correction is live until the matching API and Firebase
assets are deployed from this repair commit. Existing approved customer HTML
is immutable and is not automatically regenerated by a renderer update.
